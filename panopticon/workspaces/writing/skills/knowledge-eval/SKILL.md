# SKILL.md

## Trigger

- 当任务包含"资料是否足够 / 观点能不能写 / 大纲怎么立 / 哪些断言需要来源 / 是否可发布"时
- 当需要对写作 brief、来源充分性、对外内容做正式判断时
- 当输出需要"结论 + 依据来源 + 限制 + 待核实项"时

## Steps

1. 先整理主题、受众、语气、来源要求与风险等级。
2. 运行 `scripts/run_eval_artifact.py` 发起知识评估。
3. 检查 `artifacts/<task_id>/artifact.md` 和 `artifacts/<task_id>/artifact.json`。
4. 若 `summary.status=no_hit` 或 `weak_hit`，明确写出来源不足与待核实项，不编造细节。
5. 再输出 writing 风格结论：大纲/判断、来源依据、限制、是否需要 Review。

## Exit Criteria

本 skill 完成的条件（满足任意一条即可退出）：

1. **结论已输出**：已产出明确的判断（可发 / 不可发 / 待补来源），写到 artifacts/。
2. **来源缺口已标记**：若无法完成评估，已输出明确的缺口清单（缺什么来源、去哪里找、补完后谁继续）。
3. **被外部中断**：用户在评估过程中切换任务或明确说"跳过评估"，记一笔到 artifact 后退出。

不允许以"先欠着，后面补"的方式跳过结论输出而退出。

## Red Flags（必须停止或升级的情况）

遇到以下任一情况，立即停止执行并报告给用户：

| # | 情况 | 要求 |
|---|---|---|
| 🚩 1 | 用户要求评估的内容触及隐私/合规/合同条款边界 | 停止评估，告知用户此内容需人工法务审查 |
| 🚩 2 | 所有来源都是 `no_hit` 或 `weak_hit` | 不得编造细节填补缺口；仅输出缺口清单 |
| 🚩 3 | 用户要求"跳过评估直接发" | 记录到 artifact 的 decision log，不阻止但必须标注 ⚠️ 未经评估 |
| 🚩 4 | eval 脚本运行失败（网络/API/文件错误） | 停止，输出错误信息，不清除前序 artifact |
| 🚩 5 | 用户要求修改评估结论以匹配偏好 | 不接受；输出原文结论 + 在 decision log 中记录"用户要求修改结论但未采纳" |

## Common Excuses（常见绕过理由）

当 Agent 或用户试图用以下理由跳过评估时，应在输出中标出对应 warning：

- **"先发布，后面再补来源"** → ⚠️ 不可接受。对外内容应在发布前完成评估。
- **"这个观点很明显，不用查"** → ⚠️ 没有明显观点。每个断言都要有来源。
- **"大概够了吧"** → ⚠️ 评估结论不能模糊。必须输出明确的状态（pass / need_rework / blocked）。
- **"先写满字数，后面再砍"** → ⚠️ 信息来源决定字数上限，不是反过来。
- **"参考了 N 篇，但不需要一一列出"** → ⚠️ 必须列出被采纳和被拒绝的引用及其理由。
