# 单页简报网格版式

> 4-6 个信息模块的 executive one-pager / briefing page。
> 目标是在 1280x720 内完成“结论、证据、风险、行动”的闭环，而不是把多页 deck 硬压成一页。

适用：给老板/客户/投资人快速决策的一页简报、项目周报、问题诊断、方案摘要、经营仪表盘。

## 重力场哲学

单页简报不是平均分配空间，而是一个有明确阅读顺序的高密度情报板：

1. **标题带先给结论（Executive takeaway）**：顶部不是封面标题，而是“今天要拍板什么”的一句话结论。
2. **KPI 行快速定量**：2-4 个指标用极短标签建立事实锚点。
3. **主洞察占最大块**：一张 anchor 卡承担最关键的判断或图表。
4. **行动/风险在侧边收束**：右侧或底部放建议、风险、下一步，服务决策。
5. **来源细条低调落地**：来源与注释放成 source strip，不与页脚争空间。

## 推荐空间模型

以 12 栏为思维模型，不要求机械写死：

```text
┌──────────────────────────────────────────────┐
│ 标题结论带：1 行主结论 + 1 行情境/对象       │
├──────────┬──────────┬──────────┬────────────┤
│ KPI 1    │ KPI 2    │ KPI 3    │ KPI 4/状态 │
├──────────────────────┬─────────┬────────────┤
│ 主洞察 / 核心图表     │ 证据块  │ 行动建议   │
│ anchor: 5-7 栏        │ support │ risk/next  │
├──────────────────────┴─────────┴────────────┤
│ 来源 / 假设 / 更新时间 source strip          │
└──────────────────────────────────────────────┘
```

## 模块数量建议

- 最小：1 个标题结论带 + 3 个 KPI + 1 个主洞察 + 1 个行动建议。
- 标准：1 个 anchor + 3 个 KPI/support + 1 个 risk + 1 个 next-step。
- 上限：最多 6 个有 `data-card-id` 的主卡片；更多信息应合并成列表或 source strip。

## 内容预算

- 标题结论：不超过 28 个中文字符或 12 个英文词。
- KPI 卡：标签 4-8 字，数值 1 个，解释最多 1 行。
- 主洞察卡：正文最多 3 bullet，或 1 张图表 + 1 行解释。
- 行动/风险卡：每块 2-3 条，每条不超过 18 个中文字符。
- 来源条：10-11px，高对比，最多 2 行。

## 灵动化指引

### 用层级而不是边框制造丰富感

高密度页很容易变成表格。优先使用以下层级手段：

- anchor 卡使用 `accent` / `elevated`，面积最大。
- KPI 用 `transparent` / `outline`，让数值自己发光。
- risk/next-step 用窄色条、编号、小图标，不要再加厚边框。
- 来源条只用轻底色或细分割线，不做卡片阴影。

### 阅读顺序必须可见

- 从左上结论开始，经过 KPI，再进入主洞察，最后落到行动建议。
- 可以使用 1-2 条细线、编号、微箭头或色块流向提示。
- 不要让 6 个模块都抢视觉中心。

### 高密度不等于小字号

- 正文尽量保持 13.5-15px。
- 注释/来源可用 10-11px，但必须高对比。
- 如果需要 12px 以下正文才能放下，说明内容没有被压缩，应回到 planning 合并信息。

## 禁忌

- 禁止平均 2x3 卡片墙，没有主次。
- 禁止把封面式大标题占掉 40% 高度。
- 禁止在底部同时堆 source、caption、页脚、图例。
- 禁止用 `scale()` 或负 margin 把多页内容硬塞进单页。
