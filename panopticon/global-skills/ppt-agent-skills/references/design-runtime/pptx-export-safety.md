# PPTX 导出安全护栏

> 面向本仓库的双导出链路：HTML -> PNG / SVG -> PPTX。
> 目标不是限制创意，而是降低截图通过、导出翻车的概率。

## 1. 适用范围

- 适用于所有 `1280x720` 单页 HTML。
- 优先约束 `content` / `toc` 这类信息密度较高的页面。
- `cover` / `section` / `end` 可以更激进，但只要出现正文、列表、图表或页脚，就应回到本规范。

## 2. 保守安全区（推荐值）

这些值比基础设计规范更保守，适合首次成稿与高密度页面：

| 区域 | 推荐值 | 最低值 | 说明 |
|------|--------|--------|------|
| 顶部内容起点 | 96-112px | 80px | 避开统一标题区和装饰遮挡 |
| 左右边距 | 72-88px | 48px | 图表/表格页优先用 80px 左右 |
| 底部安全区 | 84-96px | 64px | 给页脚、下沉字形和导出裁切留缓冲 |
| 主内容最大高度 | 520-540px | 560px 内 | 超过后优先减内容，不要先硬缩放 |

建议把高密度页的核心内容框理解为：

```css
.content-safe-zone {
  position: absolute;
  top: 104px;
  left: 80px;
  right: 80px;
  bottom: 92px;
}
```

## 3. 字号与间距安全值

| 元素 | 推荐范围 | 保守值 | 风险信号 |
|------|----------|--------|----------|
| 页面标题 | 24-30px | 26px | > 34px 容易挤压 header |
| 卡片标题 | 16-22px | 18px | < 15px 易失层级 |
| 正文段落 | 14-17px | 15px | < 13px 可读性明显下降 |
| 列表项 | 14-16px | 15px | 多层列表尽量不用 |
| 注释/来源 | 10-12px | 11px | < 10px 导出后易发虚 |
| 大数字/KPI | 56-104px | 72px | > 120px 常挤占支撑区 |

| 间距项 | 推荐值 | 保守值 |
|--------|--------|--------|
| 卡片内 padding | 14-22px | 18px |
| 标题下间距 | 12-18px | 14px |
| 段落下间距 | 8-12px | 10px |
| 列表项间距 | 4-6px | 4px |
| 组块之间 gap | 18-28px | 20px |

硬规则：

- 正文 `line-height` 保持在 `1.45-1.7`。
- 标题 `line-height` 保持在 `1.1-1.25`。
- 最后一个正文元素 `margin-bottom: 0`。
- 当页面出现裁切风险时，先减冗余文案、减纵向 gap、增安全区，不要先把全页字号一起压小。

## 4. 高风险版式的保守解法

### 图表 / 表格页

- 优先使用左右分栏或整页主图布局。
- 不要把“标题 + 三段正文 + 图表 + 注释”竖着堆满全页。
- 图表下方若必须有说明，限制为 1-2 行 caption。
- 可提升为 `NativeChart:*` 或命名原生 group 的图表，必须给出稳定 bbox：容器宽度低于 360px 时，优先改为 KPI / metric_row / ring 这类低标签密度图表，不要强塞 comparison_bar、radar 或 stacked_bar。
- 图表标签使用 `font-size: clamp(10px, 1.15vw, 13px)` 或同等保守映射；标签超过 8 个字符时改为短标签 + caption，不要依赖旋转文本解决拥挤。
- 若数据系列超过 5 组或分类超过 6 个，先在 planning 阶段聚合为 Top-N + Others；不要把完整明细交给 HTML 通过缩放硬塞。
- 图例优先右上角或底部单行，宽度不足时改为内联颜色标记；禁止让图例占用主绘图区超过 18% 高度。

### 多卡片信息页

- 每页尽量控制在 2-4 个主卡片。
- 如果 anchor 卡已经很大，support 卡只保留最关键的 1-2 个证据点。
- 出现拥挤时，优先减少卡片数，而不是继续缩小字号。

### 高密度 / 单页简报页

- 仅当用户明确要求高密度、或 planning 使用 `one-pager-grid` / `visual_weight>=8` 时启用；不要把所有普通页都做成情报板。
- 主卡片上限 6 个，必须有明显 anchor；禁止平均 2x3 表格墙。
- 正文下限建议 `13.5px`，最低不得低于 `13px`；caption / source 可用 `10-11px`，但对比度必须明显高于背景。
- 来源条、图例、caption、页脚不得同时挤在底部同一条带；至少拆成“内容 source strip”和“全 deck footer”两个视觉层级。
- 内容安全区可以贴近最低值，但底部仍需保留 64px 以上物理缓冲；页脚与 source strip 间距不低于 20px。
- 用短标签、KPI、metric row、action rail、编号流向提升密度；禁止靠 `scale()`、负 margin、全页 12px 正文硬塞。

### 图片页

- 图片容器为正文预留独立空间，不让图片和正文争同一纵向高度。
- 图片若贴近底部，额外加 12-20px 底部缓冲。

## 5. Review 阶段的优先修复顺序

当截图出现底部裁切、页脚贴边、文字压线、图表标签拥挤时，按这个顺序处理：

1. 删减非核心文案或合并重复支撑点。
2. 提高底部安全区或改成双栏布局。
3. 缩小局部卡片标题 / caption，而不是先缩小全页正文。
4. 最后再调整装饰层和阴影范围。

## 6. 一眼判定信号

出现以下任一信号，就说明已经进入危险区：

- 页脚与正文的垂直距离小于 24px。
- 某个卡片正文超过 6 行仍未分栏或裁剪。
- 图表标签必须旋转或挤成两行才能放下。
- KPI 数字占满一整列后，support 内容被迫缩成注释字级。
- 大段内容必须依赖 `scale()`、负 margin 或绝对定位硬塞回画布。

## 7. 设计原则

- 安全区是为了保住阅读体验，不是为了把页面做得保守乏味。
- 视觉冲击优先交给锚点、色块、材质和构图，不要交给贴边与拥挤。
- 同一页里，宁可少一点内容，也不要让观众怀疑这页会在 PPTX 里炸版。
