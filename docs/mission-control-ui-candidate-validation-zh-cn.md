# Mission Control 实页基线与候选验收

记录日期：2026-11-01。状态：任务卡候选已实现，技术回归通过，人工可用性验收待完成。

## 范围与比较方法

- 代表性页面：主看板 Mission Queue，沿用真实 API 和现有详情。
- 基线是本轮任务卡 CSS 修改前的工作区预览，不是仓库 HEAD 或十主题参考页面。
- 候选仅调整 [任务卡样式](../MissionControl/assets/styles.css)，不改变排序、筛选、数据、组件 ID、状态流转和刷新机制。
- 在同一已加载页面更新样式，89 张任务的 ID、标题及负责人完整签名一致。实时指标和 Feed 仍会更新，不作为冻结数据比较。
- 桌面前后截图和手机候选截图已留在本次会话。未部署生产、提交任务、认领任务、发布评论或操作 Agent。

## 已验证

- 1280px 桌面保持五列；320/390px 手机保持纵向状态分组，均无页面横向溢出。
- 这批真实任务的标题及负责人在上述视口没有裁切，不等同于任意长度文本保证。
- Enter 打开真实详情，焦点进入关闭按钮；Esc 关闭后焦点返回原任务卡。
- 27 项 [UI 回归测试](../MissionControl/tests/test_ui_callbacks.py) 通过，交互脚本语法检查通过，样式无编辑器诊断。
- 现有测试涵盖失败 API 状态保持、首次失败五秒重试、辅助读取独立失败及按任务隔离草稿。

## 扩展门槛

1. 对同一数据快照交替使用基线与候选：找到 INBOX 任务、说出负责人、找到 REVIEW 任务并辨识结果；记录耗时、误选及额外滚动，每个任务至少重复三次。
2. 定位时间中位数和误选次数不得增加。没有人工计时，不宣称更快；先完成视觉偏好确认。
3. 在隔离测试数据中完成认领、评论和状态流转，验收成功/失败反馈与草稿保留，不对生产任务做写入验收。
4. 补齐错误/离线实页：冷启动失败、已有快照后失败、恢复连接、详情读取失败；明确区分过期快照和空数据。
5. 补测超长负责人/标题、无标签、多标签、长结果、390x360 短屏弹窗、屏幕阅读器和文本对比度。
6. 同环境量化冷/热首屏、详情打开延迟及筛选业务 API 调用数；本轮尚未完成这些比较。

门槛完成前仅保留候选预览，不扩展十主题或独立大屏。通过后先覆盖主看板和弹窗，再单独评估大屏实际用途。

## 状态可读性第一阶段

2026-11-01 后续实现，独立候选预览为 <http://127.0.0.1:9092/>，未重启原有 9091 服务、部署生产或写入任务数据。

- Agent 新增可见的 `Recently active`、`Idle`、`Unknown` 标签，不再仅依赖颜色。近期活跃仍按原逻辑取最近 30 分钟内的看板或 Feed 活动，不代表连接健康；空闲也不代表离线。缺失或未知状态仅在展示层归为 `Unknown`。
- 初始页面显示 `Connecting...` 和各区块加载占位；首次失败显示对应区块的加载失败及重试提示，不再呈现为空白。
- 已有成功快照后的失败提示明确标记 `showing cached data`，保留最后同步时间、旧数据及原五秒重试逻辑。API 提示增加 polite live region，长文字允许换行。
- 语音延迟区分 `Overlay disabled` 与 `Overlay: no samples`，有样本时保留原 p50/p95 和阈值配色。
- 31 项 UI 回归测试通过，新增覆盖 Agent 状态文字、未知状态、初始加载、失败快照保留及语音三种状态；交互脚本语法检查和三个修改代码文件的编辑器诊断通过。
- 真实只读预览显示 8 个 Agent、89 张任务。1440/1280px 桌面保持五列，390/320px 手机保持原纵向状态分组；均无页面横向溢出，实际 Agent 名称与状态文字未裁切。已检查桌面及手机 Agent 区域截图。
- 无凭据预览的首次 401 失败提示在上述四种宽度可完整换行；随后加载已有 UI 配置，预览恢复在线。已有快照后断线仍仅由单测覆盖，未人为中断生产连接。
- 三种 Agent 状态文字在白底上的对比度分别为 6.53:1、6.94:1、6.42:1。完整屏幕阅读器体验尚未人工验收。

新增状态行有密度成本：1440px 当前首卡约 124px，高于前一候选记录的约 106px；没有固定数据快照的效率计时，不能据此宣称任务定位更快。
截至第一阶段，任务搜索、顶栏重组、手机分视图及触控尺寸调整尚未实施，前述扩展门槛继续适用。

## 任务定位第二阶段

2026-11-01 后续实现，继续使用独立 9092 候选预览，不改原有 9091 服务或生产部署。

- 搜索栏按标题、完整 ID、显示 ID 或负责人做大小写不敏感的子串匹配，支持中文。范围仅为当前已加载的任务快照，不是后端全局搜索，不搜索任务结果、评论或标签。
- 搜索停止输入约 350ms 后应用；与原有看板、Feed 筛选共存，并将条件编码到 URL 的 `q` 参数，刷新后恢复。清除筛选同时复位搜索与两处分类筛选。
- 搜索和清除位于 Mission Queue 内，顶栏不再放置清除按钮；无条件时按钮禁用。总览任务数保持原口径，搜索摘要显示匹配数和已加载数，状态列显示匹配数及原计数，空列显示 `No matching tasks`。
- 本地筛选不变更卡片顺序、任务 ID、状态、原始快照或动态列表内容；新快照刷新后继续应用查询。36 项 UI 回归测试通过，包括本地筛选无业务 API 读取、URL 恢复、复位、快照完整性及刷新后保留查询；脚本语法检查通过。
- 真实列表 89 张任务：`NOX` 匹配 55 张，完整 ID、显示 ID 和一段中文标题分别匹配 1 张；无结果查询匹配 0 张。浏览器逐项核对结果 ID 与原始可见列表一致，清除后恢复 89 张。
- 搜索与 Comments 筛选共同使用并刷新页面，查询和筛选正确恢复；匹配任务 Enter/Space 打开详情，Esc 关闭后焦点返回原卡片。未认领、评论或变更任务状态。
- 1440/1280px 仍保持五列，390/320px 仍为纵向状态分组；页面和搜索栏均无横向溢出。手机搜索、清除、分区筛选控件实际高度为 44px，桌面分别为 36/36/30px。

搜索不读业务 API 的结论来自模拟调用计数回归，不代表页面停止正常实时更新，也不是整个系统的请求量基准。任务定位耗时、首次加载性能及完整屏幕阅读器体验仍未人工量化。
完整顶栏导航重组、负责人独立筛选及手机分视图尚未实施，不增加后端 API，不改默认任务排序或折叠状态列。
